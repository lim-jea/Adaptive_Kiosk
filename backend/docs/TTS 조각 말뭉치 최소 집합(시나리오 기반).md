# TTS 조각 말뭉치 최소 집합 (시나리오 기반)

목표
- 음성 주문 파이프라인의 **응답 문장들을 가능한 한 적은 수의 WAV 조각**으로 표현한다.
- 런타임에서는 `audio_segments`를 사용해 **조각 WAV를 이어붙여 즉시 재생**하고,
  조각 캐시 미스 시에만 `response_text` 전체 합성(또는 브라우저 TTS 폴백)을 사용한다.

전제(현재 구현)
- 조각 WAV는 `backend/data/tts_cache/`에 개별 WAV로 저장된다.
- `audio_segments`가 있으면 백엔드가 `compose_audio_from_segments(segments)`를 먼저 시도한다.
- 조각 문자열은 **정확히 같은 텍스트(공백 포함)**여야 캐시 hit 된다.

## 1) 시나리오 응답 전수(현재 canned_responses.json 기준)

아래 응답들은 FastPath(canned)에서 즉시 반환되는 **대표 시나리오 응답**이다.

- 인사

- 추천(카테고리 질문)
  - "어떤 종류가 좋으세요? 커피, 티, 스무디 중에 골라주세요."
- 긍정/부정
  - "네, 알겠습니다."
  - "알겠습니다. 다른 걸 도와드릴까요?"
- 전체 취소
  - "주문을 취소할게요. 다음에 또 오세요."
- 도움/반복/대기
  - "원하시는 음료 이름을 말씀해 주세요."
  - "다시 말씀드릴게요."
  - "네, 천천히 말씀하세요."
- 카테고리 이동
  - "커피 메뉴 보여드릴게요."
  - "티 메뉴 보여드릴게요."
  - "스무디 메뉴 보여드릴게요."
  - "에이드 메뉴 보여드릴게요."
- 스크롤
  - "더 보여드릴게요."
  - "위로 올려드릴게요."
- 장바구니/결제
  - "장바구니 열어드릴게요."
  - "결제 화면으로 이동할게요."
  - "결제를 진행할게요."
- 종료 인사
  - "주문 완료되었습니다. 감사합니다."
- 옵션(프리뷰 안내)
  - "톨 사이즈 선택했어요. 다음 옵션을 알려주세요."
  - "차갑게 준비할게요."
  - "따뜻하게 준비할게요."

  - "죄송해요, 주문만 도와드릴 수 있어요."

추가로, 메뉴 선택/옵션 선택/장바구니 요약 등은 템플릿 기반(`templates.parts`) 또는 조각 기반(`fragments`)으로 이미 조합 가능하다.

## 1-1) 운영 시 추가로 자주 필요한 시나리오(확장 고려)

Gemini가 처리하는 구간(= canned/pattern/menu fast-path가 아닌 구간)에서 특히 자주 등장하는 “추가 시나리오”들이다.
아래 항목들은 **조각/템플릿으로 안정화**해두면 응답 지연과 문장 흔들림이 크게 줄어든다.

- 인식 실패/재질문
  - "잘 못 들었어요. 다시 말씀해 주세요."
- 메뉴 모호성(동명이인/유사 메뉴 다수)
  - "비슷한 메뉴가 여러 개 있어요. (후보) 중에서 어떤 걸로 드릴까요?"
- 필수 옵션 미결정
  - "필수 옵션이 남아 있어요. 옵션을 선택해 주세요."
- 수량 확인
  - "수량은 몇 잔으로 할까요?"
- 장바구니 비어 있음
  - "장바구니가 비어 있어요." / "먼저 메뉴를 담아주세요."
- 장바구니 조작 확인(담기/빼기/수량 변경)
  - "{menu}를 장바구니에 담았어요."
  - "{menu}를 장바구니에서 빼드릴게요."
  - "장바구니에서 {menu} 수량을 {n}로 바꿨어요."

## 2) 최소 말뭉치(조각) 집합 설계

원칙
- 너무 잘게 쪼개면(특히 1~2음절) Gemini TTS가 무음/불안정한 경우가 있어, **의미 단위(절/구)** 수준으로 자른다.
- 조합이 많이 일어나는 부분만 세분화한다.
  - 예: `{menu}`, `{option}`, 가격 숫자(십/백/천/만)는 조각화 가치가 큼
  - 반면 짧은 상투어는 1개 조각으로 두는 게 안정적

권장 확장(운영 안정화용)
- 재질문/모호성/확인 질문용 조각을 별도로 둔다(문장 흔들림 방지)
- 장바구니 조작(담기/빼기/수량 변경) 확인 문장을 템플릿으로 고정한다

현재 최소 집합(추가된 fragments.static + 기존 fragments/static)
- 연결구/숫자 단위
  - 기존: `", "`, `" 주문하셨습니다."`, `" 총 "`, `" 원입니다."`, `" 십 "`, `" 백 "`, `" 천 "`, `" 만 "` 등
- 시나리오 문장 조합용 핵심 조각(새로 추가)
  - `"안녕하세요."`
  - `" 어떤 음료로 주문하시겠어요?"`
  - `"어떤 종류가 좋으세요? "`
  - `" 중에 골라주세요."`
  - `" 메뉴 보여드릴게요."`
  - `"더 보여드릴게요."`
  - `"위로 올려드릴게요."`
  - `"장바구니 열어드릴게요."`
  - `"결제 화면으로 이동할게요."`
  - `"결제를 진행할게요."`
  - `"주문 완료되었습니다."`, `" 감사합니다."`
  - `"알겠습니다."`, `" 다른 걸 도와드릴까요?"`
  - `"주문을 취소할게요."`, `" 다음에 또 오세요."`
  - `"원하시는 음료 이름을 말씀해 주세요."`
  - `"다시 말씀드릴게요."`
  - `"네, 천천히 말씀하세요."`
  - `"톨 사이즈 선택했어요."`, `" 다음 옵션을 알려주세요."`
  - `"차갑게 준비할게요."`, `"따뜻하게 준비할게요."`
  - `"죄송해요,"`, `" 주문만 도와드릴 수 있어요."`
- 카테고리 조각(새로 추가)
  - `"커피"`, `"티"`, `"스무디"`, `"에이드"`, `"주스"`

### 2-1) 메뉴/옵션 조각(동적 집합) — **핵심**

`audio_segments` 조합에서 가장 중요한 가변 슬롯은 `{menu}` / `{option}`이다.

이 둘은 정적 fragments.static에 하드코딩하지 않고, **DB에서 전수 수집되는 동적 말뭉치 집합**으로 취급한다.

- 메뉴 조각 집합
  - 원천: DB의 `Menu.name` 전체
  - 용도: 템플릿 parts의 `{menu}` 슬롯, 주문 요약/장바구니 안내 등
  - 예(시드 기준):
    - 커피: 에스프레소, 따뜻한 아메리카노, 아이스 아메리카노, 따뜻한 카페라떼, 아이스 카페라떼, 카푸치노, 콜드브루, 콜드브루 라떼, 드립 커피
    - 달콤한커피: 바닐라 라떼, 카라멜 마끼아또
    - 블렌디드: 프라푸치노, 말차 프라페
    - 티: 녹차 라떼, 캐모마일 티
    - 달콤한티: 복숭아 아이스티, 자몽 허니 블랙 티
    - 에이드: 레몬에이드, 자몽에이드
    - 스무디: 딸기 스무디, 망고 스무디
    - 주스: 오렌지 주스

- 옵션 조각 집합
  - 원천: DB의 `OptionItem.name` 전체
  - 용도: 템플릿 parts의 `{option}` 슬롯, 옵션 확정/옵션 안내 등
  - 예(시드 기준):
    - 사이즈: Tall, Grande, Venti
    - 온도: HOT, ICE
    - 샷 추가: 샷 추가 (+1)
    - 시럽: 바닐라 시럽, 헤이즐넛 시럽, 카라멜 시럽
    - 휘핑크림: 휘핑크림 추가
    - 당도: 기본, 덜 달게, 더 달게

중요
- 동적 집합이므로 운영 중 메뉴/옵션이 바뀌면 “말뭉치 집합”도 함께 바뀐다.
- 따라서 프리워밍은 **정적 조각 + DB의 메뉴/옵션 조각**을 합쳐 캐시에 채우는 방식이어야 한다.

## 3) 시나리오 → 조각 조합 매핑(예시)

- greet_general
  - segments: `["안녕하세요.", " 어떤 음료로 주문하시겠어요?"]`
- ask_recommend
  - segments: `["어떤 종류가 좋으세요? ", "커피", ", ", "티", ", ", "스무디", " 중에 골라주세요."]`
- category_*
  - segments: `["{카테고리명}", " 메뉴 보여드릴게요."]`
- cancel
  - segments: `["주문을 취소할게요.", " 다음에 또 오세요."]`
- farewell
  - segments: `["주문 완료되었습니다.", " 감사합니다."]`

이 매핑은 이미 backend/data/canned_responses.json에 `audio_segments`로 반영되어 있다.

## 4) 다음 단계(검증/운영)

1) 조각 WAV 프리워밍
- scripts/prewarm_tts_segments.py 를 사용해 조각들을 캐시에 채운다.
- Gemini TTS 호출 한도가 작을 수 있으니 `--limit`로 소량부터 테스트한다.

권장 실행(메뉴/옵션까지 포함)
- `uv run python scripts/prewarm_tts_segments.py --include-db --limit 50`

정적 조각만 테스트(빠름)
- `uv run python scripts/prewarm_tts_segments.py --limit 50`

2) 실제 시나리오 검증
- canned 시나리오가 매칭될 때:
  - `audio_segments` 조합이 캐시 hit → 응답 지연 거의 0
  - 캐시 미스 → response_text 합성(또는 브라우저 폴백)

3) 확장(필요 시)
- 카테고리/문장 다양화가 필요하면 fragments.static 또는 templates(parts)를 늘리되,
  기존 문자열은 변경하지 않는다(캐시 키/기존 WAV 재사용에 영향).
