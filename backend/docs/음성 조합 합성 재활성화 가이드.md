# 음성 조합 합성(audio_segments) 재활성화 가이드

> 현재 상태: **비활성**. 매 응답을 `synthesize_speech(response_text)`로 통째 합성한다.
> 시나리오 매뉴얼에 등록된 응답만 디스크 캐시에서 즉시 hit, 그 외는 매번 Gemini TTS 호출.

조합 합성을 다시 켜면 AI가 `audio_segments` 배열에 조각 텍스트를 채우고, 백엔드가 미리 합성된 조각 WAV들을 PCM으로 이어붙여 하나의 응답 음성으로 만든다. Gemini TTS 호출이 거의 0회로 떨어지지만, 단일 음절 합성 실패와 RPM(429) 한도 같은 운영 이슈가 있어 비활성화한 상태다.

비활성화는 **코드 4곳만** 되돌리면 즉시 복구되도록 정리했다. 데이터(JSON 매뉴얼·디스크 캐시)와 헬퍼 함수는 그대로 남아 있다.

## 사전 점검 — 무엇이 그대로 남아 있나

| 항목 | 위치 | 상태 |
|---|---|---|
| `audio_segments` 스키마 필드 | [`schemas/chat.py`](../schemas/chat.py) `AIChatResponse` | 그대로 (현재는 "AI는 채우지 말 것" 코멘트만) |
| `compose_audio_from_segments` (PCM concat + 트림 + 크로스페이드) | [`services/canned_responses.py`](../services/canned_responses.py) | 그대로 |
| `expand_template_texts` / `expand_fragment_texts` | [`services/canned_responses.py`](../services/canned_responses.py) | 그대로 |
| `template_to_segments` / `compose_template` / `price_to_segments` | [`services/canned_responses.py`](../services/canned_responses.py) | 그대로 |
| `get_template_phrases_for_prompt` / `get_fragments_for_prompt` | [`services/canned_responses.py`](../services/canned_responses.py) | 그대로 |
| `data/canned_responses.json` 의 `templates` / `fragments` 섹션 | [`data/canned_responses.json`](../data/canned_responses.json) | 그대로 |
| 디스크 캐시 (`data/tts_cache/`) | 디스크 | 그대로 (시나리오 응답만 채워져 있음) |

→ 따라서 **삭제된 코드는 없다**. 다시 import 하고 호출하기만 하면 된다.

## 재활성화 절차 (4단계)

### 1) `api/v1/endpoints/voice.py` — 조각 합성 분기 복구

현재:

```python
from services.chat_service import process_voice_message, synthesize_speech


async def _audio_for_response(response):
    """response_text 전체를 통째로 합성. 디스크 캐시 hit이면 즉시 반환."""
    return await synthesize_speech(response.response_text)
```

다음으로 되돌린다:

```python
from services.canned_responses import compose_audio_from_segments
from services.chat_service import process_voice_message, synthesize_speech


async def _audio_for_response(response):
    """audio_segments가 있으면 조각 합성으로, 없으면 라이브 합성으로 폴백."""
    if response.audio_segments:
        composed = compose_audio_from_segments(response.audio_segments)
        if composed is not None:
            return composed
    return await synthesize_speech(response.response_text)
```

### 2) `services/chat_service.py` — 시스템 프롬프트에 매뉴얼 다시 주입

import 블록에 다음을 추가:

```python
from services.canned_responses import (
    all_canned_texts,
    expand_fragment_texts,           # ← 추가
    expand_template_texts,           # ← 추가
    get_cached_wav,
    get_canned_phrases_for_prompt,
    get_fragments_for_prompt,        # ← 추가
    get_template_phrases_for_prompt, # ← 추가
    match_canned,
    save_cached_wav,
)
```

`process_chat_message` 안의 stage_context 빌드 부분을 되돌린다:

```python
# 현재 (비활성)
canned_block = get_canned_phrases_for_prompt(current_stage)
if canned_block:
    stage_context = f"{canned_block}\n\n{stage_context}"

# 재활성
canned_block = get_canned_phrases_for_prompt(current_stage)
template_block = get_template_phrases_for_prompt()
fragment_block = get_fragments_for_prompt()
prefix_blocks = [b for b in (canned_block, template_block, fragment_block) if b]
if prefix_blocks:
    stage_context = "\n\n".join(prefix_blocks + [stage_context])
```

### 3) `services/chat_service.py` — `prewarm_tts_cache`가 다시 DB 슬롯 확장

현재 시나리오 텍스트만 합성한다. 템플릿 정적 부분 + fragment(메뉴/옵션/숫자/연결구)도 합성하도록 복구:

```python
async def prewarm_tts_cache(db_factory=None) -> int:
    if _get_client() is None:
        return 0

    phrases: list[str] = list(all_canned_texts())

    if db_factory is not None:
        try:
            async with db_factory() as db:
                phrases.extend(await expand_template_texts(db))
                phrases.extend(await expand_fragment_texts(db))
        except Exception as e:
            logger.warning("[chat_service] 템플릿/조각 확장 실패: %s", e)

    phrases = list(dict.fromkeys(p for p in phrases if p))

    n = 0
    for phrase in phrases:
        try:
            if await synthesize_speech(phrase):
                n += 1
        except Exception:
            pass
    logger.info("[chat_service] TTS 프리워밍 완료: %d/%d", n, len(phrases))
    return n
```

### 4) `scripts/prewarm_tts.py` — `_collect_phrases`도 DB 확장 복구

```python
async def _collect_phrases() -> list[str]:
    """시나리오 + 템플릿×DB + 조각을 모두 모아 중복 제거한 리스트 반환."""
    from core.database import get_session_factory, initialize_connection_pool
    from services.canned_responses import (
        all_canned_texts,
        expand_fragment_texts,
        expand_template_texts,
    )

    phrases: list[str] = list(all_canned_texts())

    try:
        await initialize_connection_pool()
        factory = get_session_factory()
        if factory:
            async with factory() as db:
                phrases.extend(await expand_template_texts(db))
                phrases.extend(await expand_fragment_texts(db))
    except Exception as e:
        logger.warning("DB 연결 실패 — 템플릿/조각 확장 건너뜀: %s", e)

    return list(dict.fromkeys(p for p in phrases if p))
```

### 5) `schemas/chat.py` — 코멘트만 원복 (선택, 동작에 영향 없음)

```python
# 변경 전 (현재)
# (현재 비활성) 조합형 응답용 음성 조각 배열. 백엔드가 무시하고 response_text를 통째 합성한다.
# AI는 이 필드를 채우지 말 것.
audio_segments: Optional[List[str]] = None

# 변경 후
# 조합형 응답: 조각 텍스트 배열을 채우면 백엔드가 미리 합성된 조각 WAV를 이어붙여 즉시 재생.
# 조각 중 하나라도 캐시에 없으면 response_text를 통째로 라이브 합성으로 폴백.
audio_segments: Optional[List[str]] = None
```

## 재활성화 후 해야 할 일

```bash
# 1. 컴파일 검증
uv run python -m py_compile services/chat_service.py api/v1/endpoints/voice.py scripts/prewarm_tts.py

# 2. 대상 텍스트 확인 (예상: 시나리오 22 + 템플릿 정적 ~10 + 조각 ~60 = 약 90개)
uv run python -m scripts.prewarm_tts --list

# 3. 조각 합성 (RPM 429 회피용 cooldown 옵션 권장)
uv run python -m scripts.prewarm_tts --cooldown 90

# 4. 정상 합성된 항목이 [v]로 표시되는지 다시 확인
uv run python -m scripts.prewarm_tts --list
```

## 비활성화 결정 배경 (재활성화 시 다시 부딪힐 이슈)

| 이슈 | 원인 | 회피 방법 |
|---|---|---|
| **`'NoneType' object has no attribute 'parts'`** | Gemini TTS가 `","`, `"에 "`, `"일"` 같은 단일 음절/조사에 빈 응답을 돌려보냄 | `data/canned_responses.json`의 정적 조각에 양 옆 공백 추가 (`" 일 "`). 이미 적용되어 있음. 그래도 실패하면 `synthesize_speech`의 `_is_too_short_for_tts` 폴백으로 무음 WAV 대체. |
| **429 Too Many Requests** | Flash TTS 무료 티어 RPM ~15. 90개를 즉시 보내면 절반은 막힘 | `--delay 4.5` (기본) + `--cooldown 60`. 재시도 두 번 모두 429면 자동 abort. |
| **단어 사이 끊김** | 조각마다 TTS가 자동으로 50~200ms 무음을 붙임 | `compose_audio_from_segments`가 `_trim_silence` + `_crossfade(25ms)`로 처리. `_SILENCE_THRESHOLD` / `_CROSSFADE_MS`로 튜닝. |
| **AI가 잘못된 segments 반환** | response_text와 segments 의미 불일치 | `_call_gemini_structured`에서 길이 차 `>max(3, len/4)`이면 segments 무시 후 라이브 합성 폴백. 이미 활성. |
| **음성 모델 변경 시 캐시 충돌** | 같은 텍스트인데 다른 voice로 합성된 옛 파일이 재생됨 | `canned_responses.py` 의 `_CACHE_KEY_VERSION = "kore-v1"` 을 올린 뒤 `--clean` 후 재합성 |

## ⚠️ Gemini TTS preview 모델의 실제 한도 (2026-04 확인)

비활성화의 **근본 원인**이 된 한도다. 재활성화 시 반드시 이 표를 먼저 확인할 것.

### 일일 한도 (RPD) — 결제 등급(티어)과 무관

| 모델 | RPD | 비고 |
|---|---|---|
| `gemini-2.5-flash-preview-tts` | **100 / 일** | preview 단계라 **티어 1 결제 사용자도 동일** |
| `gemini-2.5-pro-preview-tts` | **50 / 일** | 폴백으로 쓰면 오히려 더 빨리 소진됨 |

> 로그에서 직접 확인:
> ```
> Quota exceeded for metric: generate_requests_per_model_per_day
> limit: 100, model: gemini-2.5-flash-tts
> ```

이 한도는 **AI Studio 대시보드(`https://aistudio.google.com/rate-limit`)에 표시되지 않는다**. preview 모델 특유의 별도 quota라서 실제로 호출해 봐야 알 수 있다.

### 무엇을 의미하는가

- 시연 1회당 10~30 turn × `/voice/start` 1회 = 보통 **10-30회 호출**
- 시나리오 매뉴얼에 매칭되지 않는 응답마다 1회씩 소모
- → 하루 약 **3-10회 시연** 가능
- 디스크 캐시(`data/tts_cache/`)에 한 번 저장되면 그 텍스트는 영구적으로 quota 소모 없음

### 재활성화 시 quota 영향

조합 합성(audio_segments)을 다시 켜도 **prewarm 한 번이 100 RPD를 즉시 소진**한다.
시나리오 22 + 템플릿 정적 ~10 + 조각 ~60 = 약 90개 → 하루치 100 RPD 거의 전부를 prewarm 한 번에 소진하면 그날 시연용 라이브 합성은 거의 불가능.

대응책:
1. **prewarm을 여러 날에 나눠서 실행** — `--list` 출력에서 `[ ]` 표시된 것이 줄어들 때까지 반복
2. **이미 합성된 항목은 자동 건너뜀** — `--clean` 하지 않으면 누적
3. **시연 직전에는 prewarm 금지** — 시연 당일 quota를 보존할 것

### chat 모델은 별개

chat용 [`_GEMINI_MODEL`](../services/chat_service.py)은 `gemini-3.1-flash-lite-preview` 사용 중. 이건 **티어 1에서 RPD 수만 회 / RPM 수천** 수준으로 매우 넉넉. quota 걱정 없음.

### 폴백 모델을 추가하지 않는 이유

[`core/config.py`](../core/config.py)에서 `GENAI_TTS_FALLBACK_MODEL`은 의도적으로 두지 않는다.

- Pro TTS(50/일)가 폴백되면 Flash 한도 100을 다 쓰고 나서 50까지 추가 소진하고 끝남
- 결과적으로 quota는 더 빨리 소진되고 음성 품질도 떨어지는 모델로 호출됨
- 그냥 Flash 단일 호출 → 실패 → 프런트의 브라우저 `speechSynthesis` 폴백이 깔끔

### 결국 시연 안정화 전략

| 단계 | 방법 |
|---|---|
| 단기 (현재) | 시나리오 매뉴얼 22개를 디스크 캐시에 박아두고 매뉴얼에 없는 응답은 브라우저 TTS 폴백 |
| 중기 (조합 재활성) | 위 가이드대로 코드 복구 후 prewarm을 **여러 날에 걸쳐** 실행해 90개 디스크 적재 |
| 장기 (TTS GA 또는 대안) | 2.5 TTS가 GA 출시되면 한도 1000+/일로 자동 확장 / 또는 Google Cloud TTS Neural2(월 100만자 무료)로 이중화 |

## 단계별 부분 활성화 (옵션)

조합 합성 전체가 부담스러우면 단계적으로 켤 수 있다.

**Level 1 — 템플릿만 활성** (메뉴 N개를 한 템플릿 K개로 처리):
- voice.py 의 `_audio_for_response`만 되돌리고
- chat_service의 prefix_blocks에 `template_block`만 추가
- 메뉴 이름은 fragments 없이 그냥 통째 합성 (메뉴 수만큼 디스크 합성 필요)

**Level 2 — fragments까지 활성** (현재 가이드 기준 완전 활성)

**Level 3 — Gemini Live API 전환** (REST 폐기):
- 양방향 WebSocket 기반 native streaming TTS
- 아키텍처 전면 재작성 필요 — 시연용 ROI 낮아 보류
