## 📊 1. Mode A - 상황 기반 추천 분석

### 1.1 데이터 흐름 (완전 객관적)

```
📋 CSV 데이터 (11,729 주문)
    ↓
🔍 필터 1: 성별 필터링 (estimated_gender)
    - 예: gender="M" → 남성 사용자 주문만 추출
    ↓
🔍 필터 2: 연령대 필터링 (estimated_age_group)
    - 예: age_group="30~39" → 30대 주문만 추출
    ↓
🔍 필터 3: 시간대 필터링 (created_at → hour 추출)
    - morning: 06:00 ~ 11:00
    - lunch: 11:00 ~ 14:00
    - afternoon: 14:00 ~ 18:00
    - evening: 18:00 ~ 22:00
    - night: 22:00 ~ 06:00
    ↓
📈 통계: 필터링된 주문에서 음료 빈도 계산
    popularity = menu_count / total_items_in_situation
    ↓
⚡ 트렌드 가중치 적용 (Naver API 실시간 데이터)
    trend_weight = Naver API 검색량 기반 (0.5~2.0)
    ↓
⏰ 시간대 가중치 적용 (CSV 데이터 기반)
    hour_weight = CSV의 시간별 주문 빈도 (0.5~1.5)
    ↓
🎯 최종 점수 계산
    final_score = popularity × trend_weight × hour_weight
    ↓
🏆 상위 N개 추천
```

### 1.2 각 계산 단계별 객관성 검증

| 단계 | 데이터 소스 | 계산 방식 | 객관성 | 하드코딩 |
|------|-----------|---------|--------|---------|
| 성별 필터링 | CV 주문 기록 | exact match | ✅ 완전 객관적 | ❌ 없음 |
| 연령대 필터링 | CV 주문 기록 | exact match | ✅ 완전 객관적 | ❌ 없음 |
| 시간대 필터링 | created_at 타임스탬프 | hour extraction | ✅ 완전 객관적 | ⚠ 시간대 경계값* |
| 인기도 계산 | 필터링된 주문 수 | count / total | ✅ 완전 객관적 | ❌ 없음 |
| 트렌드 가중치 | Naver API 7일 검색량 | 평균 계산 | ✅ 완전 객관적 | ❌ 없음 |
| 시간대 가중치 | CSV 시간대별 주문 | Min-Max 정규화 | ✅ 완전 객관적 | ❌ 없음 |

```python
# 실제 호출 코드
def _fetch_from_naver(self, beverage_name: str, gender: str, age_group: str) -> float:
    """

    2️⃣ 지난 7일 기간 설정 (시작: 현재날짜-7일, 종료: 현재날짜)
    3️⃣ 성별/연령대를 Naver API 형식으로 변환
    4️⃣ API 요청 본문 생성
    5️⃣ HTTP POST 요청으로 API 호출
    6️⃣ 응답에서 검색 지수(ratio) 추출
    7️⃣ 평균 계산 및 가중치 변환
    """
```

### 3.2 트렌드 가중치 계산식 (완전 객관적)

```
1. Naver API 응답: 지난 7일의 일일 검색 지수 배열 [80, 85, 90, 92, 88, 86, 84]
   
2. 평균 계산:
   avg_ratio = (80 + 85 + 90 + 92 + 88 + 86 + 84) / 7 = 87.9
   
3. 정규화 공식:
   weight = 1.0 + (avg_ratio - 50) / 50.0
   
   ✓ avg_ratio = 50 → weight = 1.0 (중립, 변화 없음)
   ✓ avg_ratio = 0 → weight = 0.5 (최저)
   ✓ avg_ratio = 100 → weight = 2.0 (최고)
   
   예시:
   - avg_ratio = 87.9 → weight = 1.0 + (87.9 - 50) / 50 = 1.76x (높은 트렌드)
   - avg_ratio = 45 → weight = 1.0 + (45 - 50) / 50 = 0.9x (낮은 트렌드)
   
4. 범위 제한 (안전장치):
   weight = max(0.5, min(2.0, weight))
```

## ⏰ 4. 시간대 가중치 상세 분석

### 4.1 시간대 가중치 계산 로직 (완전 객관적)

```python
def _calculate_hourly_weights(self):
    """
    CSV 주문 데이터에서 추출한 시간대별 가중치 계산
    """
    # 1️⃣ 모든 주문의 created_at에서 시간 추출
    orders_copy['hour'] = pd.to_datetime(orders_copy['created_at']).dt.hour
    
    # 2️⃣ 시간별 주문 건수 계산
    hourly_counts = orders_copy['hour'].value_counts()
    # 예: {9: 152, 10: 189, 11: 234, 12: 256, ...}
    
    # 3️⃣ Min-Max 정규화 (0.5 ~ 1.5 범위)
    max_count = hourly_counts.max()        # 최대값 (예: 256)
    min_count = hourly_counts.min()        # 최소값 (예: 65)
    range_count = max_count - min_count
    
    for h in range(24):
        count = hourly_counts.get(h, 0)
        if count == 0:
            weight = 0.5  # 주문 없는 시간 → 최소 가중치
        else:
            # 정규화: (count - min) / range * 1.0 + 0.5
            normalized = (count - min_count) / range_count
            weight = 0.5 + normalized  # 0.5 ~ 1.5
        
        self.hourly_weights[h] = round(weight, 2)
```
