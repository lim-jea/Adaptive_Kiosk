# 외부 기기 접속 설정 정리

이 문서는 Docker 없이 로컬에서 백엔드와 프론트엔드를 실행한 뒤, 같은 Wi-Fi의 다른 기기 또는 ngrok 링크로 접속하는 방법을 정리한다.

## 1. 핵심 원리

외부 기기에서 접속할 때 문제가 되는 지점은 보통 두 가지다.

- 프론트가 `localhost:5000` 백엔드를 호출하면, 외부 기기에서는 그 기기의 `localhost`를 보게 된다.
- 핸드폰 카메라와 일부 음성 기능은 일반 HTTP 외부 IP에서 브라우저 보안 정책으로 막힐 수 있다.

따라서 현재 프로젝트는 프론트 Vite dev server가 `/api` 요청을 로컬 백엔드로 프록시하도록 설정한다.

외부 기기 브라우저:

```text
http(s)://프론트주소/api/...
```

프론트 Vite proxy:

```text
http://127.0.0.1:5000/api/...
```

이렇게 하면 외부 기기는 백엔드 `5000` 포트에 직접 접근하지 않아도 된다.

## 2. 프론트 환경변수

`frontend/.env`의 API 주소는 상대 경로로 둔다.

```env
VITE_API_URL=/
VITE_KIOSK_API_KEY=발급받은_키오스크_API_KEY
VITE_ENCRYPTION_ENABLED=false
```

이번 외부 접속 설정에서 실제로 바꾼 내용은 아래와 같다.

변경 전:

```env
#VITE_API_URL=http://localhost:5000
VITE_API_URL=http://172.30.1.70:5000
VITE_KIOSK_API_KEY="발급받은_키오스크_API_KEY"
VITE_ENCRYPTION_ENABLED=false
```

변경 후:

```env
#VITE_API_URL=http://localhost:5000
VITE_API_URL=/
VITE_KIOSK_API_KEY="발급받은_키오스크_API_KEY"
VITE_ENCRYPTION_ENABLED=false
```

`VITE_API_URL=/`로 둔 이유는 프론트가 백엔드를 직접 호출하지 않고, 현재 접속한 프론트 주소의 `/api`로 요청하게 만들기 위해서다. 이후 Vite proxy가 이 요청을 내부 백엔드 `http://127.0.0.1:5000`으로 전달한다.

주의:

- `VITE_API_URL=http://localhost:5000`이면 외부 기기에서 실패한다.
- `VITE_API_URL=http://내PC_IP:5000`도 동작할 수 있지만, 방화벽/CORS/Mixed Content 문제를 피하려면 `/` + proxy 방식이 더 안정적이다.
- `.env`를 바꾼 뒤에는 프론트 dev server를 재시작해야 한다.

## 3. Vite proxy 설정

`frontend/vite.config.js`의 `server` 설정은 아래 형태가 필요하다.

```js
server: {
  host: '0.0.0.0',
  port: 5173,
  allowedHosts: true,
  proxy: {
    '/api': {
      target: 'http://127.0.0.1:5000',
      changeOrigin: true,
    },
  },
}
```

역할:

- `host: '0.0.0.0'`: 다른 기기에서 프론트 dev server에 접속 가능하게 한다.
- `allowedHosts: true`: ngrok 같은 외부 호스트 주소 접근을 허용한다.
- `proxy['/api']`: 프론트로 들어온 `/api` 요청을 백엔드로 전달한다.

## 4. 백엔드 실행

PowerShell:

```powershell
cd "C:\Users\jeayy\Desktop\26년도 산학협력캡스톤\Adaptive_Kiosk\backend"
uv run uvicorn main:app --reload --host 127.0.0.1 --port 5000
```

프론트 proxy가 백엔드에 접근하므로 백엔드는 `127.0.0.1:5000`에 떠 있어도 된다.

로컬 확인:

```text
http://127.0.0.1:5000
```

정상 응답 예:

```json
{"message":"Adaptive Kiosk API is running"}
```

## 5. 프론트 실행

PowerShell:

```powershell
cd "C:\Users\jeayy\Desktop\26년도 산학협력캡스톤\Adaptive_Kiosk\frontend"
npm run dev
```

로컬 확인:

```text
http://localhost:5173
```

같은 Wi-Fi의 다른 기기에서 접속하려면 PC의 Wi-Fi IP를 사용한다.

예:

```text
http://172.30.1.70:5173
```

PC IP 확인:

```powershell
ipconfig
```

`Wi-Fi` 항목의 `IPv4 Address` 값을 사용한다.

## 6. ngrok으로 외부 HTTPS 링크 만들기

핸드폰 카메라 기능까지 쓰려면 HTTPS가 필요하다. 이 경우 프론트만 ngrok으로 열면 된다.

프론트와 백엔드를 먼저 실행한 뒤, 새 PowerShell에서:

```powershell
ngrok http 5173
```

ngrok이 출력한 HTTPS 주소로 접속한다.

예:

```text
https://abcd-1234.ngrok-free.app
```

이 방식에서는 백엔드 ngrok을 따로 열 필요가 없다. 프론트 Vite proxy가 내부에서 `http://127.0.0.1:5000` 백엔드로 요청을 넘긴다.

## 7. 테스트 순서

1. PC에서 백엔드 확인

```text
http://127.0.0.1:5000
```

2. PC에서 프론트 확인

```text
http://localhost:5173
```

3. 같은 Wi-Fi 핸드폰에서 프론트 확인

```text
http://내PC_IP:5173
```

4. 카메라 기능까지 확인할 때는 ngrok HTTPS 주소로 접속

```text
https://ngrok주소
```

5. 청년/중년 같은 수동 선택 버튼이 다음 화면으로 넘어가는지 확인

이 버튼이 실패하면 대부분 `POST /api/v1/sessions` 생성이 실패한 것이다. 이 경우 `VITE_KIOSK_API_KEY` 값과 백엔드 실행 여부를 먼저 확인한다.

## 8. 자주 나는 문제

### 카메라 인식이 안 됨

일반 HTTP 외부 IP 접속에서는 브라우저가 카메라 접근을 막을 수 있다.

해결:

```powershell
ngrok http 5173
```

ngrok HTTPS 주소로 접속한다.

### 수동 나이 선택 버튼도 안 넘어감

세션 생성 API 호출이 실패했을 가능성이 높다.

확인할 것:

- 백엔드가 `127.0.0.1:5000`에서 실행 중인가?
- `frontend/.env`의 `VITE_API_URL=/` 설정 후 프론트를 재시작했는가?
- `VITE_KIOSK_API_KEY`가 유효한가?
- Vite proxy 설정이 들어가 있는가?

### 핸드폰에서 `http://내PC_IP:5173` 접속 자체가 안 됨

확인할 것:

- PC와 핸드폰이 같은 Wi-Fi에 연결되어 있는가?
- 프론트가 `host: '0.0.0.0'`로 실행 중인가?
- Windows 방화벽이 Node/Vite 또는 5173 포트를 막고 있지 않은가?
- 학교/회사 Wi-Fi처럼 기기 간 통신을 차단하는 네트워크가 아닌가?

## 9. 현재 추천 구성

개발/시연용으로는 아래 구성을 추천한다.

```text
백엔드: 127.0.0.1:5000
프론트: 0.0.0.0:5173
프론트 env: VITE_API_URL=/
프론트 proxy: /api -> http://127.0.0.1:5000
외부 접속: ngrok http 5173
```

이렇게 하면 외부 접속 링크는 하나만 관리하면 되고, 카메라 기능도 HTTPS 환경에서 테스트할 수 있다.
